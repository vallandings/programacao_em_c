# 🧩 Raciocínio Lógico: O "Antes" do Código

Programar não é apenas digitar comandos técnicos. É, antes de tudo, a arte de organizar o pensamento. Aqui, registro como aprendi a decompor problemas complexos em etapas que o computador consegue executar.



## 🍰 A Analogia da Receita
Imagine que você precisa ensinar um robô a fazer um bolo. Se você disser apenas "faça um bolo", ele vai travar. Ele precisa de uma sequência lógica e detalhada:

1.  **Decomposição:** Não é apenas "fazer bolo". É quebrar em: separar ingredientes, preparar a massa, pré-aquecer o forno, assar, esperar esfriar.
2.  **Precisão:** Você não pode dizer "misture os ingredientes". Precisa dizer "misture 200g de farinha com 3 ovos por 5 minutos".
3.  **Condições:** "Se o bolo estiver dourado, desligue o forno. Se ainda estiver mole, deixe por mais 10 minutos".

**O computador é esse robô.** Ele não tem intuição. Se você esquecer de dizer para ele ligar o forno, ele vai entregar a massa crua sem reclamar. Aprender lógica é aprender a prever esses pontos cegos.



## 🛠️ Meu Toolkit de Lógica
Para não "pular etapas" e garantir que minha lógica esteja sólida antes de partir para a linguagem C, estou utilizando:

*   **Bizagi:** Uso para desenhar o "mapa" visual (fluxograma) da solução. Ajuda a ver onde o processo pode travar.
*   **Portugol Studio:** É onde escrevo o "rascunho" do código em português. É a base fundamental: se a lógica funciona no Portugol, eu sei que ela está correta.



## 🎯 Meus Objetivos
- [ ] Aprender a modelar problemas reais em fluxos de passos lógicos.
- [ ] Validar a lógica antes de codificar (evitando retrabalho na linguagem C).
- [ ] Desenvolver a capacidade de antecipar erros antes que eles aconteçam no programa.
